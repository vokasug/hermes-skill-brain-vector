# brain-vector

Векторная база поверх базы знаний `~/gdrive/Brain` — семантический поиск по
суммаризациям (`*_sum.md`) с фильтрами по метаданным. Точка входа для агента —
`SKILL.md` (триггер «мозг …»). Этот файл — для человека.

## Зачем

Быстрые ответы на вопросы по накопленной библиотеке (246+ материалов:
пересказы видео, конспекты записей Plaud, протоколы встреч) без ручного
перебора файлов. Примеры вопросов:

- «какие рекомендации по покупке ЗПИФ недвижимости за последний год»
  → семантический поиск + фильтр `folder=Finances`, `date>=…`
- «что есть с habr про новые модели ИИ за месяц»
  → поиск + фильтр по `author` и дате
- «последний статус миграции базы данных по работе»
  → поиск + `folder=Work`, выбор самого свежего по `date`
- «сводка нового за неделю» → файловая выборка по датам (без семантики)

## Что решает

- **Индексация**: разбор каждого `_sum.md` на структурные блоки (Главная
  мысль / каждый тезис / Вывод), эмбеддинг каждого блока, сохранение со
  всеми метаданными. Инкрементально (sha1), без дублей.
- **Поиск**: векторный поиск чанков + SQL-фильтры по метаданным в одном
  запросе, дедупликация до файлов, выдача топ-N со скором.
- **Обслуживание**: `optimize()` — склейка фрагментов и очистка версий.

## Технологии

- **Эмбеддинги**: `mlx-community/Qwen3-Embedding-4B-4bit-DWQ` через пакет
  `mlx-embeddings` — локально на Apple Silicon (MLX), 2560-мерные
  нормованные векторы, last-token pooling. Модель скачивается с
  HuggingFace при первом запуске (~3 ГБ).
- **Хранилище**: LanceDB (embedded, без сервера), таблица `chunks` в
  `~/brain-vector/db`. Полный перебор (flat scan) — ANN-индекс не нужен
  на этом объёме (~5k записей).
- **Python-окружение**: uv tool (`~/.local/share/uv/tools/mlx-embeddings/`).

## Как устроено

```
~/gdrive/Brain/<папка>/<дата>_<имя>.md        ← полный транскрипт/конспект
~/gdrive/Brain/<папка>/<дата>_<имя>_sum.md    ← пересказ (источник для индекса)
~/brain-vector/db/chunks.lance/               ← векторная база
scripts/brain_index.py                        ← индексация / optimize
scripts/brain_search.py                       ← поиск
```

Каждая запись в базе: `text` + `vector` + метаданные — `filename`,
`folder` (только имя папки), `title`, `author`, `date`, `link`, `section`
(мысль/тезис/вывод), `fhash` (sha1 файла для инкрементальности).

1 структурный блок = 1 запись: цельный файл не эмбеддится (размазывает
темы), агент после поиска читает sum-файл целиком — чанк только указатель.

## Функции

| Команда | Действие |
|---|---|
| `brain_index.py` | Инкрементальная синхронизация (новые/изменённые/удалённые) |
| `brain_index.py --full` | Полная пересборка базы с нуля |
| `brain_index.py --optimize` | Склейка фрагментов + очистка старых версий (без модели, секунды) |
| `brain_search.py "запрос"` | Семантический поиск, топ-5 файлов |
| `… --folder Finances` | Фильтр по папке |
| `… --author plaud` | Фильтр по автору (substring, регистронезависимо) |
| `… --after/--before YYYY-MM-DD` | Фильтр по дате публикации |
| `… --top N --chunks M` | Сколько файлов выдать / сколько чанков проверить |
| `… --verbose` | Показать все найденные чанки |

## Установка на чистый компьютер

Требования: macOS на Apple Silicon, `uv`, доступ к `~/gdrive/Brain`.

```bash
# 1. Окружение (mlx-embeddings + lancedb в одном tool-окружении)
uv tool install mlx-embeddings --with lancedb

# 2. Скрипты уже лежат в <skills>/brain-vector/scripts/ (идут со скиллом)

# 3. Инициализация базы (первая загрузка скачает модель ~3 ГБ с HF)
~/.local/share/uv/tools/mlx-embeddings/bin/python \
    scripts/brain_index.py --full

# 4. Проверка
~/.local/share/uv/tools/mlx-embeddings/bin/python \
    scripts/brain_search.py "тестовый запрос" --top 3
```

База создаётся в `~/brain-vector/db` (путь задан константой `DB` в обоих
скриптах). Источник — `~/gdrive/Brain` (константа `ROOT`).

## Обслуживание

- Новые sum-файлы → прогнать `brain_index.py` (инкрементально, ~10 с/файл).
- После массовых реиндексов или раз в месяц → `brain_index.py --optimize`.
- Смена модели эмбеддингов → только `--full` (векторы несовместимы).

## Настроенные крон-джобы (Hermes) — пример у автора

Оба джоба — `no_agent` (чистый скрипт, без LLM): пустой stdout = ничего не
отправляется, непустой (реальная индексация или ошибка) приходит в Telegram.
Обёртки лежат в `~/.hermes/scripts/` (в репозиторий не входят — локальная
склейка, ~15 строк bash: запуск скрипта uv-питоном, молчание при «без
изменений», вывод при ошибке).

| Джоб | Расписание | Что делает |
|---|---|---|
| `brain-vector-sync` | `0 */4 * * *` — каждые 4 часа от полуночи МСК | Инкрементальный `brain_index.py`. Без изменений выходит за ~1 с, не загружая модель (ранний выход по сверке sha1) и молчит. При новых/изменённых sum-файлах — индексирует и присылает отчёт; при падении — присылает хвост ошибки. |
| `brain-vector-optimize` | `0 6 * * *` — ежедневно в 06:00 МСК | `brain_index.py --optimize` (склейка фрагментов + очистка версий, модель не загружается). Молчит при успехе, пишет только при ошибке. |

Пропущенные запуски (мак спал) не критичны — следующий прогон догонит
инкрементально.
