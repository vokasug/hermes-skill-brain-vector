# Brain Vector («мозг»)

## When to Use

Триггер — слово «мозг» в начале запроса или обороты «используя мозг», «по данным
мозга», «данные мозга»:

- «мозг скажи …», «мозг ответь …», «мозг проконсультируй …», просто «мозг <вопрос>»
  → ответ на вопрос по базе (Procedure 1).
- «синхронизируй мозг / базу мозга» → Procedure 2.
- «оптимизируй мозг / базу мозга» → Procedure 3.
- «удали из мозга …», «убери из мозга …», «удали из мозга материал про …» →
  Procedure 4.

DON'T: «добавь в мозг / добавь в brain» — это скилл brain-summary, не перехватывать.

## Константы

- Источник данных: `~/gdrive/Brain/<папка>/*_sum.md`; рядом с каждым sum лежит
  полный MD-транскрипт (то же имя без суффикса `_sum`).
- База: `~/brain-vector/db` (LanceDB, таблица `chunks`).
- Python с зависимостями: `~/.local/share/uv/tools/mlx-embeddings/bin/python`
  (дальше обозначается `PY`).
- Скрипты: `scripts/brain_index.py`, `scripts/brain_search.py` (рядом с этим файлом;
  ниже — `SCRIPTS`).
- Модель: `mlx-community/Qwen3-Embedding-4B-4bit-DWQ` (2560 dim, локально на MLX;
  загрузка в память ~5–10 с при каждом вызове поиска — это нормально).

## Procedure 1 — ответ на вопрос

### Шаг 1. Разбор вопроса: фильтры и ветка

Из вопроса извлечь:

- **Тема → папка** (флаг `--folder`): финансы/инвестиции/ЗПИФ/деньги → `Finances`;
  работа/совещания/миграция/проекты → `Work`; здоровье → `Health`; семья/дети →
  `Family`; обучение/курсы → `Education`; модели/ИИ-техника/недвижимость-быт/игры →
  `Hobbies`; личные разговоры → `Private`. Тема неоднозначна или широкая —
  искать БЕЗ `--folder`.
- **Период**: «за последний год/месяц/неделю», «с марта» → `--after YYYY-MM-DD`
  (дату считать инструментально от сегодня, не в уме); «до лета» → `--before`.
- **Источник → `--author`**: «с сайта habr» → `--author habr`; «записи plaud» →
  `--author plaud`; имя YouTube-канала → как есть. Совпадение — substring,
  регистронезависимо.
- **«последняя / свежая информация по X»** → после поиска выбрать результат с
  максимальной `date` (фильтр по дате не ставить — вдруг свежих нет).

Выбор ветки:

- Тематический вопрос («какие рекомендации по ЗПИФ», «что говорят про миграцию»)
  → семантический поиск, шаг 2.
- «Сводка нового за неделю», «что добавилось» — без темы → файловая выборка по
  датам, шаг 3 (семантика НЕ нужна).
- Вопрос про конкретный материал («о чём встреча 13 апреля») → прямое чтение
  файла, поиск не нужен.

### Шаг 2. Семантический поиск

```bash
PY SCRIPTS/brain_search.py "<запрос полным предложением>" \
    [--folder Finances] [--author plaud] [--after 2026-01-01] [--before 2026-09-24] \
    --top 7 --chunks 40
```

- Запрос переформулировать в законченное предложение (модель instruct-типа:
  «какие рекомендации по покупке паёв ЗПИФ недвижимости», а не «ЗПИФ советы»).
- Для широкого тематического вопроса («что есть про X?») делать ТРИ запроса с
  синонимичной лексикой (напр. «криптовалюта» / «DeFi» / «стейблкоины, пулы
  ликвидности»): поиск чувствителен к терминам, и один запрос находит только
  файлы, написанные в тех же словах. Результаты объединить, дедуплицировать по
  файлу, скор файла = лучший скор среди всех запросов.
- **Отбор для контекста**: брать файлы, чей лучший чанк имеет скор **≥ 0.3**
  (скор в выводе = косинусная близость: ≥0.5 отлично, 0.3–0.5 релевантно,
  <0.2 шум). Из прошедших — топ-10. Если прошедших порог больше 10 — в конце
  ответа указать, сколько ещё материалов осталось за пределами выборки,
  и спросить, дочитать ли их тоже.
- **Если ни один результат не ≥ 0.3 — в базе нет данных по вопросу. Так и
  сказать, ответ не выдумывать** (проверено: запрос про habr корректно даёт
  пусто — таких материалов в Brain нет).

### Шаг 2b. Чтение контекста — всегда sum-файл ЦЕЛИКОМ

Найденный чанк — только указатель на файл. Перед ответом **прочитать каждый
отобранный `_sum.md` целиком** (≤16000 символов — дёшево): отдельный тезис без
соседних даёт фрагментарный, местами неверный ответ. Если в sum не хватает
деталей (конкретные цифры, цитаты, имена, ход рассуждения) — читать полный
транскрипт (тот же путь без `_sum` в имени).

### Шаг 3. Файловая выборка по периоду (без семантики)

```python
import pathlib, datetime
days = 7  # из вопроса
since = (datetime.date.today() - datetime.timedelta(days=days)).isoformat()
fs = sorted(f for f in (pathlib.Path.home() / "gdrive/Brain").rglob("*_sum.md")
            if f.name[:10] >= since)
```

Прочитать sum-файлы периода → сводка по папкам/темам. Для «что нового по работе»
добавить фильтр по папке.

### Шаг 4. Ответ

- Форматирование: между абзацами и пунктами списков оставлять пустые строки —
  слипшийся текст в Telegram читается плохо.
- Сначала прямой ответ, затем детали, в конце — список использованных источников:
  `папка/имя файла, дата, автор`.
- Опираться только на найденные материалы; противоречия между ними отражать,
  а не заметать.
- Если данные устарели (последний материал по теме старый) — указать дату
  последнего.

## Procedure 2 — синхронизация («синхронизируй мозг»)

```bash
PY SCRIPTS/brain_index.py
```

Инкрементально: эмбеддит только новые/изменённые sum-файлы (сверка sha1),
записи удалённых файлов чистит. ~5–10 с на файл + загрузка модели.
Когда запускать: по просьбе; после массового добавления sum-файлов; после
пакетной правки метаданных. Полная пересборка с нуля: `--full` (после смены
модели эмбеддингов — обязательно).

## Procedure 3 — optimize («оптимизируй мозг»)

```bash
PY SCRIPTS/brain_index.py --optimize
```

`tbl.optimize()`: склеивает фрагменты данных и удаляет старые версии таблицы —
файлов в `~/brain-vector/db` снова становится ~5–10. Модель не загружается,
работает секунды. Когда: по просьбе; после реиндекса >50 файлов; раз в месяц
при регулярном пополнении.

## Procedure 4 — удаление материала («удали из мозга …»)

Удаление = перенос MD-файлов в корзину macOS + чистка записей в векторной базе.
**Файлы никогда не удаляются безвозвратно — только в Корзину** (системная
команда `/usr/bin/trash`, поддерживает «Положить обратно» в Finder).

### Шаг 1. Найти кандидатов

Искать среди sum-файлов (семантический поиск из Procedure 1 тоже подходит,
если запрос тематический):

```bash
# по имени файла
find ~/gdrive/Brain -iname "*ключевое_слово*" -name "*_sum.md"
# по содержимому (название в метаданных sum)
grep -ril "ключевая фраза" ~/gdrive/Brain --include="*_sum.md"
```

Каждому найденному `_sum.md` соответствует полный MD-транскрипт рядом (тот же
путь без суффикса `_sum`) — удаляется ПАРА: и sum, и транскрипт.

### Шаг 2. Правило однозначности — ЗАПРЕТ на удаление при сомнении

- Если запрос пользователя указывает ровно на один материал (точное название,
  дата + тема, единственное совпадение) — переходить к шагу 3.
- **Если однозначно определить файл(ы) нельзя** (несколько подходящих материалов,
  расплывчатая формулировка, совпадений ноль или больше одного) — **удалять
  ЗАПРЕЩЕНО**. Сначала задать пользователю уточняющий вопрос и перечислить
  кандидатов списком: `папка/имя файла, дата, название из метаданных sum`.
  Удаление выполнять только после того, как пользователь явно выбрал вариант(ы).
- Даже при однозначном совпадении перед удалением коротко назвать, что именно
  будет удалено, если есть хоть малейшее сомнение, что пользователь имел в виду
  именно это.

### Шаг 3. Удалить записи из векторной базы

Ключ записей — имя sum-файла (поле `filename`); модель эмбеддингов не нужна:

```python
PY - <<'EOF'
import lancedb, pathlib
tbl = lancedb.connect(pathlib.Path.home() / "brain-vector/db").open_table("chunks")
names = ["2026-04-13 пример_sum.md"]  # имена удаляемых sum-файлов
for n in names:
    before = tbl.count_rows()
    tbl.delete(f"filename = '{n.replace(chr(39), chr(39)*2)}'")
    print(f"{n}: удалено записей {before - tbl.count_rows()}")
EOF
```

### Шаг 4. Перенести файлы в Корзину

```bash
trash "/Users/alexander/gdrive/Brain/<папка>/<имя>_sum.md" \
      "/Users/alexander/gdrive/Brain/<папка>/<имя>.md"
```

Порядок важен: сначала чистка базы (шаг 3), потом файлы — пока файл на месте,
можно перепроверить имя. Если транскрипта без `_sum` не оказалось — удалить
только sum и отметить это в отчёте.

### Шаг 5. Отчёт пользователю

Обязательно указать КОНКРЕТНО:

- какие `.md` файлы (полные пути: и `_sum.md`, и транскрипт) перенесены в
  Корзину macOS;
- данные какого sum-файла удалены из векторной базы (по имени файла — НЕ
  перечислять отдельные записи/чанки).

Синхронизация после восстановления файлов из Корзины НЕ нужна вручную: крон
brain-vector-sync (`0 */4 * * *`) сам подхватит вернувшиеся файлы и почистит
записи удалённых. Optimize после удаления тоже не предлагать: крон
brain-vector-optimize (`0 6 * * *`) делает это ежедневно.

## Pitfalls

- Если материалы противоречат друг другу в проверяемом факте (написание названия,
  цифра, дата — напр. «GPT-6 Soul» в одних транскриптах и «GPT-6 Sol» в других),
  не выбирать вариант по частоте или свежести источника: свериться веб-поиском и
  дать официальный вариант, отметив, что расхождение — из транскрипции.
- Файлы с автором `unknown` (не Plaud и не YouTube: конспекты курсов, отчёты)
  под фильтры `--author plaud`/канал НЕ попадают — при пустом результате
  проверить, не в этом ли дело.
- Порог 0.3 — не формальность: ниже него модель начинает подтаскивать файлы
  «хоть что-нибудь». Пустой ответ честнее мусорного.
- Вопрос «последняя информация по X» решается сортировкой по `date` из
  метаданных, а не усилением семантики — свежесть и релевантность разные оси.
- Поиск не видит файлы, добавленные после последней синхронизации: если вопрос
  про «самое свежее», а синк давно не был — сначала Procedure 2, потом поиск.
